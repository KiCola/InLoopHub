# Obsidian 文章操作与验证

本轮采用已确认的方案：保留 `index.md` 正文入口，统一当前文章与操作目标。

## 交互约定

- 打开正文或点击列表标题即选择文章；点击面板保留选择，不遍历其他已打开文章猜测目标。
- InLoop 面板在右侧栏打开；已有中间分屏面板在重新打开时迁至右侧栏。点击标题仅复用中间工作区的 Markdown 编辑页，没有编辑页时新开标签。
- 预览优先填满侧栏可用宽度，随拖动自动重新排版，长文纵向滚动；旧的固定宽度设置不再限制预览。
- 面板显示当前文章标题与路径。查看普通笔记时保留已经选择的文章，以面板明确显示的目标为准。
- 预览、校验、复制、打开产物都绑定当前文章；切换或编辑后，旧的异步结果不得覆盖当前结果。
- 正文改名不自动恢复，也不修改内容；面板提示恢复 `index.md`，文章标题在 `title` 属性中修改。
- 预览明确显示更新中、已更新和失败原因；产物信息只显示当前文章的有效构建结果。
- 「发布前检查」调用 `check <文章> --publish`，汇总属性、图片与正文转换提示，不写产物；有明确行号时可定位源文件，另列微信人工复核清单，不宣称覆盖微信端排版。

## 实施与验证计划

1. 在 `plugin/scripts/unit.mjs` 复现多文章失焦选错、跨文章产物串用及改名后的状态问题，再修改 `main.ts` 的选择与构建记录。
2. 在同一测试入口模拟宿主边界，验证标题打开、异步切换和更新失败；修改 `view.ts` 的标题按钮、当前文章提示与预览状态。
3. 用 `plugin/scripts/smoke.mjs` 验证单篇校验的警告和错误能从 Python 返回到插件；对齐 `inloop/cli.ts` 的单篇响应类型。
4. 运行 `npm run check`、Python 测试、Ruff 与 `git diff --check`，审阅差异后提交推送。

## Obsidian 人工验收

发布排版：展开预览上方“发布排版”，分别验证全局、文章覆盖、恢复继承；
调整后编辑器字体不变，预览与新构建采用新设置。切换文章后不串用未保存输入。

1. 重载插件，打开 A，再点列表中的 B 标题：B 在编辑区打开，右侧面板保留，当前文章、列表高亮与预览一致。
2. 点击面板，再执行校验、复制、打开产物：目标仍为 B。
3. B 更新尚未结束时切回 A：B 的结果不得显示在 A 的预览中。
4. 修改正文并等待保存：预览更新；修改为错误属性时，校验显示具体问题。
5. 将正文改为其他文件名：出现恢复提示，不能误构建另一篇；改回 `index.md` 后恢复。
6. 微信粘贴后的排版、图片和代码空白由人在微信中另行验证。
7. 点击 InLoop 图标确认面板位于右侧栏，其他侧栏插件仍保留；拖动边界变窄、变宽，确认预览填满可用宽度，并且点击文章仍在中间编辑区打开。
