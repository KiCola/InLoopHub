# 发布排版：设计与验证计划

用户已确认：编辑区字体不变，右侧提供折叠的发布排版设置，预览、复制和上传共用结果。

- 字体风格：系统默认、无衬线、衬线；不加载外部字体。
- 正文字号、主标题字号、行距、段间距可单独覆盖；空值沿用上一级。
- 优先级：当前文章 > 全局 > 现有主题。主标题字号控制 h1，h2–h6 每级递减 2px，最低 12px。
- 全局指当前工具仓库；文章以内容根与文章 id 区分，重命名正文不影响设置。
- 配置存于 config/publishing-typography.json，不进入 Git，不改 Markdown 或 Obsidian 设置。
- 点击“应用并刷新”保存；“恢复继承”移除所选范围的覆盖。切换文章时丢弃未应用输入。
- 字体写到文字元素自身；保留代码等宽字体、代码字号、上标和图注字号。
- 不配置时产物保持原样。CLI 构建和上传自动读取配置，插件无需另传一份参数。

本轮步骤与验证：

1. 补配置优先级、异常输入、实际产物及源文不变的失败测试，实现持久化和渲染覆盖。
2. 增加排版读取/保存 CLI，验证 JSON 输出、恢复继承及与发布构建共用结果。
3. 接入侧栏表单，验证文章切换、保存失败、旧构建失效和新预览刷新。
4. 运行 Python 全套、Ruff、插件检查；核对差异后提交推送。

微信端字体替换与真实 Obsidian 操作需现场验证，自动测试不替代手机预览。

## 使用

1. 重载插件，在右侧选择文章，展开预览上方的“发布排版”。
2. 选择“当前文章”或“全局默认”。空字段继承上一级，字段会提示全局继承值。
3. 设置字体和数值，点击“应用并刷新”。预览更新成功后再构建并复制或上传。
4. “恢复继承”清除所选范围的设置。全局恢复不会删除其他文章的单独设置。

API 上传沿用同一份配置，但本轮不新增上传按钮，也不改变微信账号权限。
已经上传的草稿不会自动更新。Obsidian 的编辑字体、主题与 Markdown 均不改变。

命令行：`inloop typography <文章>` 读取；加 `--settings '{"font_size":18}'`
替换当前文章覆盖，加 `--global` 改全局。`--settings '{}'` 恢复继承。
机器调用加全局参数 `--json`。无衬线和衬线是字体候选组合，设备缺少时会回退。
