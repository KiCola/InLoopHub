# 发布指南

第一阶段采用**半自动**流程（任务书 §18）：程序负责生成微信兼容的 HTML 与素材，
最后一步由人复制进公众号后台并人工发布。这一版**不自动群发**。

## 为什么保留人工环节

不是为了省事，而是因为格式、图片、封面、链接这四类问题恰好都是"自动化最难判断、
肉眼一眼能看出"的类型。保留一次人工过目，比事后删文章便宜得多。

## 完整流程

```text
写 Markdown
   ↓
inloop check <article>          校验内容与素材
   ↓
inloop build-wechat <article>   生成产物
   ↓
inloop preview-wechat <article> 本地预览，确认手机上的观感
   ↓
复制 article.html
   ↓
微信公众号后台 → 新建图文 → 粘贴
   ↓
人工预览 → 人工发布
```

> 上述四条命令中，**本轮（M0）尚未实现任何一条**。当前可用命令只有
> `inloop version`、`inloop info`、`inloop root`。随着各模块完成，本文件会同步补齐
> 每条命令的真实参数与输出说明。

## 产物说明

构建后在 `dist/wechat/<slug>/` 下得到：

| 文件 | 用途 |
|---|---|
| `article.html` | **要复制到公众号的正文** |
| `article.preview.html` | 本地预览外壳，模拟手机宽度，不用于发布 |
| `metadata.json` | 标题、摘要、封面等元数据，也供后续平台接口复用 |
| `images/` | 正文图片实体文件 |
| `cover.png` | 封面图 |

## 操作要点

1. **粘贴正文，不要粘贴预览页。** `article.preview.html` 带预览外壳，粘进后台会带进多余结构。
2. **标题与摘要在后台单独填。** HTML 里的标题不参与微信的标题字段。
3. **图片需要逐张处理。** 粘贴后编辑器可能要求重新上传本地图片；图片较多时预留时间。
4. **发布前在手机上看一次。** 后台预览与手机端渲染存在差异，尤其是代码块与宽表格。

## 已知风险（需要实测确认）

粘贴含本地相对路径图片的 `article.html` 时，微信编辑器需要把图片重新上传。
多图文章的实际表现（自动上传 / 逐张手动 / 部分丢失）**尚未在真实文章上验证**。
这一点直接关系到下一阶段的自动化方案选型，因此在第一篇真实文章构建完成后，
应当专门做一次粘贴实测并记录结论。

## 第二阶段预留

任务书 §25 的 P2 列出的是自动上传图片、自动创建草稿等能力。
架构上已经为此留好接口（见 `architecture.md` 第 6 节）：构建产物中的图片是
独立文件并带结构化清单，发布阶段可在上传后回填路径，无需改动内容源。
