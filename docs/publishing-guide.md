# 发布指南

第一阶段采用**半自动**流程（任务书 §18）：程序负责生成微信兼容的 HTML 与素材，
最后一步由人复制进公众号后台并人工发布。这一版**不自动群发**。

## 为什么保留人工环节

不是为了省事。**图片是硬约束**：微信编辑器既不抓取本地文件路径，也不抓取外链图片，
正文图片只能在编辑器里逐张手动上传。这一条已在真实文章上实测确认，详见下文
「实测结论」。

## 完整流程

```text
写 Markdown
   ↓
inloop check <article>          校验内容与素材
   ↓
inloop build-wechat <article>   生成产物，并打印「发布清单」
   ↓
inloop preview-wechat <article> 本地预览，确认手机上的观感
   ↓
浏览器打开 article.html → 全选复制
   ↓
微信公众号后台 → 新建图文 → 在可视区粘贴
   ↓
逐张上传正文图片（按发布清单的顺序）
   ↓
后台单独填标题 / 作者 / 摘要，上传封面
   ↓
手机预览 → 人工发布
```

四条命令都已实现。`check` 的退出码为 `0`（无问题）或 `1`（存在 ERROR），
因此也可以直接放进 CI 作为守门检查。

## 产物说明

构建后在 `dist/wechat/<slug>/` 下得到：

| 文件 | 用途 |
|---|---|
| `article.html` | **要复制到公众号的正文** |
| `article.preview.html` | 本地预览外壳，模拟手机宽度，不用于发布 |
| `metadata.json` | 元数据、本次生效的 `render_options`、以及图片结构化清单 |
| `images/` | 正文图片实体文件 |
| `cover.png` | 封面图 |

`metadata.json` 里的 `render_options` 记录了本次构建实际生效的排版选项
（主题名、字号、行高、段间距等）。样式后续会调整，因此这份记录是回看旧文章时
"当时长什么样"的唯一依据，不要手工删改。

### 图片清单

`metadata.json` 的 `images` 是**结构化清单**，每项包含：

| 字段 | 含义 |
|---|---|
| `order` | 在产物中的顺序，从 1 开始 |
| `kind` | `body`（正文图片）或 `cover`（封面） |
| `output` | 产物内的相对路径，如 `images/architecture.png` |
| `source` | 仓库内的源路径 |
| `byte_size` | 字节数 |
| `width` / `height` | 像素尺寸 |
| `section` | 该图位于哪个标题之下（正文图片才有） |
| `alt` / `caption` | 替代文字与图注 |

这份清单有两个用途：人工插图时按 `order` 顺序、按 `section` 定位；
将来接入微信素材接口后，可据此逐张上传并回填正文路径，**无需改动内容源**。

## 实测结论（已在真实文章上验证）

| 项 | 结论 |
|---|---|
| 本地相对路径图片经粘贴 | **不会**自动上传。编辑器读不到本机文件，该位置是空的 |
| 外链图片（如 GitHub raw） | **不抓取**。粘贴后只显示成一串 URL 文字 |
| 微信官方素材接口 | 需要 AppID/AppSecret，且**必须在后台把发起请求的 IP 加入白名单**；家庭宽带 IP 不稳定时不适用 |
| 样式是否保留 | **保留良好**：标题底框、卡片、代码着色、图注、表格都活着 |
| 代码块空白 | 已修复并实测通过（此前会丢缩进与词间空格） |

因此本阶段的图片处理方式是：**构建产物里放图片文件，人在编辑器里按清单逐张上传。**

## 操作要点

1. **粘贴正文，不要粘贴预览页。** `article.preview.html` 带预览外壳，粘进后台会带进多余结构。
2. **在可视区粘贴，不要用源码模式。** 源码模式贴的是 HTML 字符串，编辑器不会渲染。
3. **微信编辑器不是 Markdown 编辑器。** 它不解析 `**加粗**`、`![图](网址)` 这类语法；
   要加粗请用编辑器工具栏，图片用工具栏上传。
4. **标题与摘要在后台单独填。** HTML 里的标题不参与微信的标题字段。
5. **图片逐张上传，顺序照发布清单。** 图片较多时预留时间。
6. **发布前在手机上看一次。** 后台预览与手机端渲染存在差异，尤其是代码块与宽表格。

## 构建时打印的发布清单

`build-wechat` 与 `preview-wechat` 结束后都会打印：

```text
发布清单
  正文图片（按顺序在编辑器里上传）：
    第 1 张  images/architecture.png  → 「Method」一节内
  封面：cover.png（在后台单独上传）
  步骤：浏览器打开 article.html → 全选复制 → 后台新建图文 → 可视区粘贴 → …
```

`→ 「Method」一节内` 是这张图所属的章节标题，用来在编辑器里定位插入位置。

## 第二阶段预留

任务书 §25 的 P2 列出的是自动上传图片、自动创建草稿等能力。
架构上已经为此留好接口（见 `architecture.md` 第 6 节）：构建产物中的图片是
独立文件并带结构化清单，发布阶段可在上传后回填路径，无需改动内容源。

**前提条件**：需要公众号的 AppID/AppSecret，并且有一台 **IP 固定**的机器发起上传请求
（或把当前 IP 加入后台白名单）。在这两个条件满足之前，图片环节无法自动化。
