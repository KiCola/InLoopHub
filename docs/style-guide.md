# 写作规范

本文只管**写作层面**的规范（怎么写）。排版与颜色属于 `styles/`，元数据字段属于任务书 §4。

## 标题

一级标题用「序号 + 分隔符 + 标题」的形式（任务书 §10）：

```markdown
## 01 · Problem
## 02 · Motivation
```

- 序号用两位数字，从 `01` 起。
- 分隔符统一用 `·`，中英文标题都能用，不要一半用 `·` 一半用 `-`。
- 不加 emoji 和装饰性符号。技术内容的可信度经不起花哨标题的消耗。

## 术语

- **首次出现**给出中英文全称，此后用统一简称：
  `具身智能（Embodied AI，EAI）`，之后统一写 EAI。
- **同一概念只用一个译名。** 例如全篇统一用"机器人学习"，不要一会儿"机器人学习"、
  一会儿"机器入学"。
- 专有名词保留厂商原始写法与大小写：`Light-O1`、`Unitree G1`、`PyTorch`。
- 英文缩写首次出现必须展开，这是任务书 §28 强调用真实技术文章验证的原因之一——
  缩写密度真实反映渲染质量。

## 代码

- 代码块必须标注语言，否则高亮失效：

  ````markdown
  ```python
  def forward(self, x):
      return self.net(x)
  ```
  ````

- 代码要能跑。贴片段时用注释标出省略的上下文，不要贴一段读者无法验证的伪代码。
- 行宽控制在 80 列内。手机屏上过宽的代码只能横向滚动，可读性很差。
- 行内代码用于函数名、变量名、命令、文件名：`repo_root()`、`--template`。

## 图片

- 必须有**有信息量的 alt**。alt 会作为图片说明显示在正文中，同时是无障碍回退。
  写 `![架构图](assets/architecture.png)`，不要写 `![](a.png)`。
- 正文配图放该文章的 `assets/` 目录，用相对路径引用。
- 尺寸建议：正文配图宽度 1080px 足够，文件控制在 3MB 以内。
- 封面比例以 2.35:1 为佳（公众号封面规格）。
- 不贴读者无法读清的截图。截图里的字号在手机上通常小得看不见，必要时重新排版成图。

## 表格

- 表格列数不要超过 4 列，手机屏放不下。
- 单元格内不放长段落，放不下就改成列表。
- 表格与代码块不要嵌套。

## 引用

引用用于：原文摘录、论文结论、他人观点。不要用引用做视觉强调——
强调请用加粗。

### 两种卡片：浅底与深底

正文里两种引用写法对应两种视觉形态，**互斥**，不要混用：

| 写法 | 呈现 | 什么时候用 |
|---|---|---|
| `> 内容` | 浅底圆角卡片 | TL;DR、要点提示、需要与正文区分的补充说明 |
| `> > 内容` | 深底圆角卡片（深色底浅色字） | 引述外部内容原文：推文、公告、外部评测、官方口径 |

判断标准很简单：**内容是你写的，用浅底；内容是别人的，用深底。**
深底的作用是让读者一眼看出"这段不是作者的话"，避免把引述误读成作者观点。

标点细节：

- 深底卡片里如果要写来源，单独起一行，不要挤在引文末尾。
- 深底卡片内可以用 `**加粗**`，会渲染成白色加粗；链接会渲染成浅蓝色。
- 一层引用里不要嵌套超过一层，再深就没有对应的样式了。

## 排版主题

排版节奏由主题决定，可在 `styles/themes/` 下切换。默认主题 `inloop` 的取向是
**标题有主色下划线、正文偏紧凑、卡片圆角无竖线**。

写作时不需要关心主题——换主题不影响正文内容，只影响观感。因此**不要在正文里
用空格或空行去"手工排版"**，那会在换主题后错位。

## 长度

- 摘要控制在 120 字以内（检查会给出提示）。
- 单篇文章没有硬性长度限制，但一级标题的数量应当控制在 3–7 个：
  少于 3 个通常不成篇，多于 7 个通常说明该拆成两篇。
