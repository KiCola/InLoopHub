# styles —— 样式事实源

本目录保存排版与配色的**唯一文字出处**，任务书 §9.3、§10 的设计规则以注释形式
写在文件里，改样式时依据与实现一起改。

## 结构

```text
styles/
├── base.css              所有主题共用：颜色、字体、图片、表格、代码、卡片配色
├── code.css              代码块的语法着色（Pygments token 色）
├── themes/
│   ├── compact.css       紧凑：行高 1.75、段间距 24px、标题蓝字 + 下划线
│   ├── standard.css      标准：行高 1.85、段间距 28px、标题居中 + 上下细线（默认）
│   └── generous.css      慷慨：行高 1.95、段间距 36px、标题主色底块
└── README.md             本文件
```

构建时按 **base → code → themes/&lt;主题&gt;** 的顺序合并，后加载的同名属性覆盖先加载的。
因此：

- **共用部分只维护一份**（颜色、字体、图片规则）→ 放 `base.css`
- **主题只负责节奏**（字号、行高、间距、标题形式、卡片圆角）→ 放 `themes/*.css`

## 切换主题

```bash
inloop themes                                   # 列出全部主题及其定位，标出当前主题
inloop build-wechat <文章> --theme generous     # 临时指定
```

永久切换改 `config/wechat.yaml` 的 `wechat.theme`。

## 渲染选项会被记录在产物里

样式会不断调整，文章却长期存在。因此每次构建都会把**当次生效的选项**写进产物：

| 位置 | 内容 |
|---|---|
| `dist/wechat/<slug>/metadata.json` 的 `render_options` | 主题名、正文字号、行高、段间距、标题样式、代码配色、图片宽度、是否内联 |
| `article.html` / `article.preview.html` 的 `<meta name="inloop:theme">` | 主题名 |

这样回头查一篇已发布的文章，能知道它是哪套样式渲染的，也能用同样的选项复现。
只拿到一个 HTML 文件时，也能从 meta 里读回主题名。

记录值**必须与产物一致**，因此渲染与记录共用同一个取值函数
（`inloop.renderer.wechat.resolve_typography`），而不是两处各算一遍。
记录与实际不符比不记录更糟——那会让人以为观感是 A、实际是 B。

## 主题与配置的分工

| 谁 | 负责 | 优先级 |
|---|---|---|
| 主题（`themes/*.css`） | 节奏（字号、行高、段间距）、标题形式、卡片外形 | **高** |
| 配置（`config/wechat.yaml`） | 主题未定义时的正文参数回退值；标题样式、代码配色、图片宽度 | 低 |

主题优先，是因为"节奏"正是各主题之间最主要的差别。配置只作回退：
新增主题时可以只写标题与卡片形式，正文基础参数自动沿用配置，不必重复抄一份。

## 两种卡片

正文里两种写法对应两种视觉形态，**互斥**，不会互相覆盖：

| 写法 | 呈现 | 用途 |
|---|---|---|
| `> 内容` | 浅底卡片 | TL;DR、要点提示、需要与正文区分的补充说明 |
| `> > 内容` | 深底卡片（深色底 + 浅色字） | 引述推文、公告、外部评测原文 |

深底卡片的文字色、加粗色、链接色、行内代码色统一在 `base.css` 定义；
各主题只覆盖圆角与内距。**不要在主题里给通用 `blockquote` 写 `background`**——
它会与深底规则竞争，导致"写了深底却渲染成浅底"。

## 新增主题

1. 在 `themes/` 下新建 `<名称>.css`
2. 只写节奏相关的规则：字号、行高、间距、标题形式、卡片圆角
3. 颜色一律用 `base.css` 里的 CSS 变量（`var(--brand-primary)` 等），不要写死色值
4. 用 `python scripts/utils/make_theme_preview.py` 生成对照页，与现有主题并排比对

## 两条硬约束

1. **只用元素/后代选择器，不要给元素加 class。** 产物要求零 class：
   class 在粘贴后可能丢失，且会成为编辑器样式重写的突破口。
   容器规则写作 `.inloop-article xxx`，构建时会去掉容器类名后匹配元素。
2. **禁止**无法内联的写法：`JavaScript`、外部 CSS、`:hover`、`::before`、`#id`、
   媒体查询。构建遇到这类选择器会**直接报错**，而不是静默跳过——
   静默跳过意味着样式悄悄丢失。

## 尺寸单位

正文排版一律用 `px`。微信编辑器会改写真相对单位，用 `em`/`rem` 会导致比例错乱。
