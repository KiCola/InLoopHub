# articles —— 默认内容目录（兜底位置）

**这个目录通常应该是空的。** 你的文章放在你自己的内容目录里，不在工具仓库中。

## 什么时候会用到它

`content_root` 的解析有四级，本目录是**第四级兜底**：

| 优先级 | 来源 |
|---|---|
| 1 | 命令行参数 `--content <路径>` |
| 2 | 环境变量 `INLOOP_CONTENT` |
| 3 | `config/site.yaml` 的 `content.root` |
| 4 | **本目录**（工具仓库内的 `articles/`） |

也就是说：上面三级都没配置时，`inloop new` 才会把文章写到这里。
这对"先本地试用一下"很方便，但正式使用应当配置一个独立的内容目录——
理由见根目录 README 的「内容与文章索引」一节（内容与工具解耦）。

## 查看当前生效的内容目录

```bash
inloop info      # 打印内容目录及其来源
```

**排查问题时先看这一条**：内容目录可以在四个地方配置，
"以为在读 A、实际在读 B"是最容易犯的错。

## 目录约定

如果文章确实落在这里，结构与 `examples/` 完全一致：

```text
articles/
└── 2026/
    └── 007-your-slug/
        ├── index.md        正文 + YAML Front Matter
        ├── cover.png       封面
        └── assets/         正文配图
```

- 一篇文章一个目录，正文固定叫 `index.md`。
- 目录名为 `NNN-slug`（三位序号 + 英文短名），只用 ASCII。
- 图片就近放在该文章的 `assets/` 下，正文用相对路径引用。

## 关于版本控制

本目录的内容**默认与仓库一起提交**（`.gitignore` 未排除它）。
如果你把文章放在本目录、又不希望它们进 Git，需要自行调整 `.gitignore`——
但更推荐的做法是把内容目录配到仓库之外。
