# articles —— 文章正文（唯一内容源）

本目录是整个仓库的**内容事实源**（任务书 §2）。GitHub 上的 Markdown 即最终内容，
其他一切（HTML、元数据、图片副本）都是从它派生的可再生产物。

## 目录约定

```text
articles/
└── 2026/
    └── 002-light-o1/        # 目录名 = 三位序号-英文 slug，只用 ASCII
        ├── index.md         # 正文 + YAML Front Matter，目录内唯一入口
        ├── cover.png        # 封面，公众号要求的 2.35:1 比例最佳
        └── assets/          # 正文配图，与文章就近管理
```

## 存放规则

- **一篇文章一个目录**，正文固定命名为 `index.md`。
- **图片就近管理。** 文章自己的配图放该文章目录下的 `assets/`，不要集中到别处。
- **禁止绝对路径。** 正文引用图片一律用相对路径，如 `![架构](assets/architecture.png)`。
- **目录名只用 ASCII**（`NNN-slug`）。文章标题可以是中文，但目录名不行——跨平台与命令行体验更稳。
- **不要手工改动已发布文章的目录名。** 目录名就是文章的定位标识；改名等于新建一篇。

## 谁能改这里

- 人可以自由编辑 `index.md` 正文。
- **程序不得改写正文。** 唯一的例外是按明确指令修改 Front Matter 中的 `status` 字段。
  这条约束见 `AGENTS.md` §1 第 4 条，是为「内容不会被脚本悄悄改坏」兜底。
