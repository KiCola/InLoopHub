# examples —— 排版示例（随仓库分发）

本目录是**随工具分发的示例文章**，不是作者的内容仓库。

## 用途

1. **演示**：让第一次接触本项目的人能看到产物长什么样。
2. **回归验证**：测试会**自动遍历本目录下的每一篇文章**做端到端构建
   （见 `tests/test_wechat_builder.py` 的 `REAL_ARTICLES`）。
   任务书 §28 明确要求"不要只用简单样例"，否则会出现"测试页面很好看、
   真正技术文章一塌糊涂"。

因此这些文章要**覆盖各种写法**，改渲染器时它们是第一道防线：

| 文章 | 覆盖的写法 |
|---|---|
| `001-hello-inloop` | 代码块、外链、列表、图片 |
| `002-light-o1` | 公式降级、表格、深浅两种卡片、重点段落、多行代码块 |
| `003-robodojo` | 多行代码块（缩进 4 层）、表格、图片、图注 |
| `006-try` | 各种行内标记（作者用来试排版的最小样例） |

## 目录结构

```text
examples/
└── 2026/
    └── 002-light-o1/
        ├── index.md        正文 + YAML Front Matter
        ├── cover.png       封面（2.35:1 为佳）
        └── assets/         正文配图
```

结构与真实内容目录**完全一致**——因为构建流程对待两者没有差别。

## 谁能改这里

- 任何贡献者都可以新增示例文章来覆盖新的写法。
- **删示例要谨慎**：测试的参数化用例按实际存在的文章展开，
  删掉会让覆盖减少。`tests/test_wechat_builder.py` 里有下限断言
  （`MIN_EXAMPLE_ARTICLES`）专门防止覆盖被悄悄削弱。

## 与真实内容的关系

作者的真实文章**不在本仓库**，而是放在 `content_root` 指向的目录里
（见根目录 README 的「内容与文章索引」一节）。因此：

- 想校验自己的文章：`inloop check --all`
- 想让自己的文章也进回归验证：把样例复制到本目录（注意不要提交隐私内容）
