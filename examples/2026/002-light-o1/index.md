# Light-O1：20Hz 人形基础模型到底意味着什么

> TL;DR：把控制频率从 5Hz 提到 20Hz，带来的主要收益不是动作更精确，而是**闭环的可用带宽变宽了**——误差来不及累积就被修正。这决定了哪些任务从"理论上能做"变成"实际上能做"。

> ⚠️ 说明：本文以"人形基础模型 + 高频控制"这一技术路线为对象做方法性拆解。

> > 文中不引用具体论文的未公开细节；涉及具体型号参数时，请以原始论文为准。
> > 本文的目的是说明**技术路线的方法性取舍**，不是评测某个具体模型。
## TL;DR

- 人形基础模型要解决的核心矛盾是：**高维动作空间**与**实时控制带宽**之间的冲突。
- 控制频率是这套系统里最容易被忽视、却最影响可用性的指标。
- 20Hz 的意义主要在三处：误差累积窗口、接触瞬态响应、以及策略对扰动的容忍度。

## Problem

用一个大模型直接输出人形机器人的关节指令，看起来是很自然的方向：视觉输入、语言指令、输出动作，端到端。

但落地时会碰到一个硬约束——**控制回路必须在有限时间内完成一次"感知 → 决策 → 执行"**。

设控制周期为 $T$，则可用计算预算是

$$
T_{\text{budget}} = T - T_{\text{sense}} - T_{\text{actuate}}
$$

在 5Hz 下这个预算是 200ms 减去感知与执行开销；在 20Hz 下只剩 50ms 减去同样开销。**频率越高，留给模型的算力越少**，这就是为什么"高频"不是简单把循环跑快一点。

## Motivation

为什么要冒这个风险提高频率？因为低频控制下有一类任务根本无法稳定完成：

| 任务类型 | 对控制频率的敏感度 | 原因 |
|---|---|---|
| 慢速行走 | 低 | 动力学慢，误差可被后续修正 |
| 抓取静止物体 | 中 | 接触瞬间需要响应 |
| 动态平衡（受推力） | 高 | 扰动后必须在几十毫秒内响应 |
| 灵巧操作（工具使用） | 高 | 接触力变化剧烈，低频会振荡 |

关键洞察是：**控制频率决定了系统能"看见"多快的动态过程**。低于某个阈值，某些动态过程在控制器眼里就是一个瞬间的脉冲，无法被调节。

## Method

一种常见做法是把系统分成两层，用不同频率运行：

![分层架构示意](assets/architecture.png "图 2：感知—表征—模型—解码—执行的分层关系")

- **慢层（低频，1–5Hz）**：跑大模型，做语义理解、任务规划、目标生成。
- **快层（高频，20–100Hz）**：跑轻量策略或控制器，把目标转成关节指令，并做实时修正。

这样分层的理由是：**语义推理不需要高频，动力学调节不能低频**。把两者塞进一个循环，就只能取一个折中值，而折中值对两边都不够好。

一个简化的快层回路大致长这样：

```python
class ControlLoop:
    """20Hz 控制回路的最小骨架。"""

    def __init__(self, policy, actuator, period: float = 0.05) -> None:
        self.policy = policy          # 轻量策略，必须在预算内跑完
        self.actuator = actuator
        self.period = period          # 20Hz -> 50ms
        self.last_target = None

    def step(self, observation) -> None:
        # 1) 读取本体感觉与视觉特征（应已完成，不在本循环内阻塞）
        state = observation.proprioception

        # 2) 推理：预算是 period 减去通信与执行开销
        target = self.policy(state, self.last_target)

        # 3) 下发并记录，供下一次修正使用
        self.actuator.write(target)
        self.last_target = target
```

注意第 3 步：**上一周期的目标会作为下一周期的输入**。这是高频控制的常见做法，也是低频控制失效的地方——周期太长，上一周期的信息已经过期。

## Architecture

分层带来的额外问题是如何在两层之间传递信息。可选的接口有三类：

1. **目标关节角**：最直接，但丢掉了快层做修正的空间。
2. **目标位姿 / 末端轨迹**：保留了一定自由度，适合抓取类任务。
3. **潜在空间目标**：信息密度高，但对齐训练分布的要求苛刻。

工程上常见的选择是 1 与 2 的组合：慢层给位姿，快层在关节空间做跟踪与修正。

## Experiment

评估这类系统时，我认为有三组指标必须同时看，只看一组会得出误导性结论：

| 指标组 | 具体指标 | 说明 |
|---|---|---|
| 任务成功率 | 分任务统计，不看总平均 | 总平均会掩盖"简单任务全成、难任务全败" |
| 动态响应 | 扰动后的恢复时间 | 直接反映控制带宽 |
| 计算实时性 | 实际周期抖动（不是均值） | 均值达标但抖动大，闭环依然不稳 |

**第二组和第三组最容易被忽略。** 一篇只报告成功率的评测，读不出系统在动态场景下的真实能力。

## Interesting Points

- **控制频率是可观测的"能力上限"信号。** 看到 5Hz 与 20Hz，就能大致判断这套系统能不能做接触密集的任务，比看模型参数量有用。
- **分层不是工程妥协，而是物理约束的反映。** 语义推理与动力学调节的时间尺度差了三个数量级，本来就不该用同一个循环。
- **抖动比均值更关键。** 周期均值 50ms、偶尔跑到 120ms 的回路，在接触任务里表现会比稳定 60ms 的更差。

## Limitations

- **高频下的模型容量受限。** 留给大模型的时间少，参数量与推理深度都要压缩。
- **两层的接口设计没有通用答案。** 传递什么信息、怎么对齐训练分布，目前仍高度依赖具体任务。
- **公开评测缺少统一的动态测试协议。** 不同论文的扰动方式不同，恢复时间无法直接比较。
- **接触建模仍是瓶颈。** 频率提高了，但接触力的建模误差不会因此自动变小。

## My Thoughts

我的判断是：**20Hz 这类指标值得关注，但不要把它当成"更强的模型"来读。**

> **它更像是一个系统级设计的取舍结果：把算力从"想得更深"挪到"反应更快"。**

这个取舍对不对，取决于目标任务的时间尺度——动态平衡与灵巧操作受益明显，
而"理解复杂指令后规划多步操作"这类任务，牺牲推理深度换控制频率可能得不偿失。

真正值得追的问题我认为是两个：

1. **两层的接口能不能学出来？** 现在大多靠人工设计，如果能端到端学到"慢层该给快层什么"，会比手工设计更优。
2. **频率与容量的置换曲线长什么样？** 如果存在某个频率之后收益急剧下降，那么继续投入高频就不划算——但我还没看到系统的实验回答这一点。
